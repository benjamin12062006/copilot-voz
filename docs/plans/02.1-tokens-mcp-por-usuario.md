# 02.1 — Tokens MCP por usuario y textos privados

Fecha de creación: 2026-10-31
Estado: Implementado y verificado localmente; migración remota pendiente
Relacionada con: [API 02](02-api-identidad-y-usuarios.md), [Blob](03-api-documentos-blob-y-markdown.md), [MCP](04-api-voz-y-mcp.md)

La sesión Clerk autentica crear/listar/revocar tokens propios. La API emite una credencial aleatoria de 256 bits, mostrada una vez, válida 30 días y limitada al envío Markdown. Turso guarda solo hash, ID, propietario, fechas y revocación. El MCP continúa genérico y envía Bearer; la API resuelve el propietario consultando Turso. No se reutiliza el token de sesión Clerk como credencial permanente de agente.

Cada versión guardada tendrá un UUID de archivo privado en `<namespace>/textos/<userId>/<fileId>.md` (o .txt). El documento mantiene su ID lógico al editarse, pero el archivo de versión cambia: evita pisadas entre escritores. La biblioteca ETag conserva metadata/original y referencias; al retirar una versión se registra la limpieza pendiente y se borra solo ese archivo. Si el proveedor falla, se conserva el pendiente para reintentar; no se confirma éxito del guardado hasta completar la limpieza. Un fallo incierto durante la escritura puede dejar un archivo sin referenciar y se documentará ese límite.

No se modifica frontend. Se entrega el contrato HTTP para su botón y se prueban aislamiento, expiración, revocación, suplantación y retención. Las migraciones nuevas se ejecutan localmente; la base remota previamente identificada como ajena no se toca sin autorización específica.
